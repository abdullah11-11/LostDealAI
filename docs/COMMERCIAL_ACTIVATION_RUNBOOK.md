## Provider cost-control acceptance

Current official OpenAI documentation distinguishes notification alerts from enforced organization/project spend limits; hard-limit responses are 429 with named spend-limit codes, and enforcement can lag tracked spend. Inspect the actual account permission, control type, threshold, enforcement flag and notification delivery before relying on it. Approve a margin for delayed tracking and bound model inputs/output/retries; test budget rejection with isolated fixtures before any separately consented paid check. LostDeal's counts are not dollars. [Official spend controls](https://developers.openai.com/api/docs/guides/spend-limits), [rate limits](https://developers.openai.com/api/docs/guides/rate-limits).

The current code rejects immediate retry of insufficient quota and project/organization spend exhaustion while keeping the existing single transient retry. Currency settings and actual billing enforcement are not claimed configured. Do not create an Admin key merely to execute this development batch.

Record owner, timeline, cause, remedy and follow-up test. Do not automatically replay events, reconcile a subscription or erase records as a generic incident action.
