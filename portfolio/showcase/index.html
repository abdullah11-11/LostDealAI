Scoring v1.0

AI analysis interprets the notes

The genuine application validates structured classifications, quoted evidence, buying intent and suggested recovery steps. Unknown or unsupported claims are rejected or treated cautiously.

Code calculates Recovery Score

50% Buying Intent + 30% reason recoverability + 20% recency, adjusted by confidence and explicit safety caps. No model call is needed to calculate it.

Buying Intent
50%+Reason recoverability
30%+Quote recency
20%

Confidence multiplier: 0.7 + 0.3 × confidence / 100. The rounded result uses High ≥70, Medium ≥45, otherwise Low. Missing evidence, weak confidence, not-qualified leads and No Action recommendations apply explicit caps.

Why this is not a prediction of revenue

A Recovery Score ranks review priority using fixed product rules. It is not calibrated conversion probability, a forecast, an amount recovered, or a promise that follow-up will succeed. Deal value remains the original quote value.

Demo scores are prepared from the unchanged real scoring formula, frozen as of 12 October 2026. The synthetic analyses were authored for this showcase, not generated live.

Boundaries that matter

Evidence stays distinct from interpretation

Standard analysis preserves bounded source excerpts. Deep adds recovery strategy for eligible access. Neither sends follow-up automatically, exposes hidden reasoning, or sets the deterministic score.

Workspace authority stays on the server

Membership and tenant ownership determine access. The browser cannot grant itself a plan, organization, model or allowance. Protected usage writes use narrow server-authorized database operations.

Failures remain visible and retryable

Strict output validation, usage reservations, operation identities and staged finalization protect explicit AI workflows. Stored results can be viewed again without another provider call.

Commercial activation remains separate

Hosted email acceptance, provider cost controls, backups and restoration, Paddle Live and real payment testing still need actual configuration and acceptance. This preview makes none of those claims.
